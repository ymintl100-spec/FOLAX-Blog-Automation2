# FOLAX 0.3.0-rc.7 — 짧은 글도 이미지 최소 4장

## 원인과 변경

운영 화면의 새 원고 생성은 본문 이미지 상한이 2장이었고, 짧은 글에서 이미지 장수를 채우지 말라는 지침과 설명형의 같은 소제목 중복 이미지 금지가 겹쳐 있었습니다.

새 이미지 사용 원고는 대표 1장 + 본문 최소 3장, 총 최소 4장을 계획·생성·검사합니다. 대표 이미지를 끄고 본문 이미지만 사용할 때는 본문 최소 4장입니다. 1,000~1,200자 분량과 기존 소제목 수는 유지합니다. 같은 소제목 안에서도 서로 다른 설명·조건·동작·비교를 각기 다른 이미지로 표현합니다. 장수 때문에 허구의 사실·경험을 만들거나 분량을 늘리지 않습니다.

새 원고 화면의 이미지 사용은 기본 선택되며 장수 기준을 표시합니다. 기존 작업 화면의 낮은 이미지 상한은 새 작업에서 최소 기준에 맞춥니다. 더 높은 상한은 유지합니다. 이미지 사용을 명시적으로 모두 끄거나 텍스트 전용 플랫폼 별도 원고를 만드는 기존 기능은 유지합니다.

단순히 이미지가 있는 상태를 통과시키지 않고 요청한 이미지·검증 상태·서로 다른 실제 파일·총 최소 장수를 확인합니다. 짧은 글이나 imageOmissions 사유로 장수 미달을 허용하지 않습니다. 부족하면 원고를 보존하고 미완료 이미지만 보완하며, 보완 한도 후에도 미달이면 완료나 자동 발행으로 처리하지 않습니다. 생성 서비스의 한도·도구 오류로 실제 이미지 생성이 실패할 수는 있습니다.

## 설치·사용

1. 기존 프로그램을 완전히 종료하고 `FOLAX-Four-Images-Download.exe`를 실행합니다.
2. 다운로드·체크섬 검사·압축 해제 후 `다운로드\BlogAuto-Windows\Naver-Blog-Automator-0.3.0-rc.7.exe`를 실행합니다. 도우미는 앱을 자동 실행하지 않습니다.
3. 새 원고 작성 화면에서 `이미지 총 4장 이상 생성 · 대표 1장 + 본문 최소 3장`을 선택한 상태로 작성합니다. 기존 이미지 상한이 낮아도 새 작업에서는 최소 4장 기준을 적용합니다.
4. 로그의 `이미지 계획: 대표 1장 · 본문 3장 · 총 최소 4장`과 생성 결과를 확인하세요. 미완료 이미지가 있으면 본문 재작성 없이 해당 새 작업의 이미지 단계부터 재개할 수 있습니다.

기존 계정·설정·원고·작업 기록·파일은 초기화하거나 삭제하지 않습니다. 이미 저장했거나 중단된 기존 작업은 원래 이미지 계획을 유지하며, 새 기준으로 이미지가 자동 추가되지는 않습니다. 최소 4장 기준은 새로 시작하는 이미지 사용 작업부터 적용합니다. 이미지 사용을 끄면 텍스트만 생성합니다.

이번 변경은 앱의 생성·검수 규칙 변경입니다. 확장이 이미 0.3.21이면 추가 확장 갱신은 필요 없습니다. 이전 버전이면 앱 실행 후 해당 계정 Chrome의 chrome://extensions에서 BlogAuto 새로고침(↻)을 눌러 주세요. 확장과 로그인 프로필은 유지합니다.

## 검증

자동 테스트 103개 통과. 1,000~1,200자 원고 + 한 소제목 안의 본문 3장 + 대표 1장, 대표 없이 본문 4장, 장수 부족/파일 재사용/파일 누락 차단, 부족한 이미지만 재시도, 완료된 4장 재개 시 모델 재호출 없음, 기존 정책 유지 및 원고 보존을 검증했습니다. 실제 Electron 화면에서는 기본 선택·최소 장수 안내·낮은 기존 상한 보정·대표 끄기 및 전체 이미지 끄기를 확인했습니다.

이미지 파일 존재 여부 테스트는 명시적인 로컬 파일 fixture를 사용했습니다. 실제 이미지 모델 호출·Windows GUI·실제 계정 발행은 이 환경에서 실행하지 않았으며, 그림 품질이나 생성 성공을 보장하지 않습니다. Windows x64 EXE를 빌드하고 패키지 소스·버전·다운로드 체크섬을 검증합니다.
