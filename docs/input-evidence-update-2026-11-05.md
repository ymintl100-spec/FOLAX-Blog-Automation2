# FOLAX 0.3.0-rc.19 — 보강 조사 중 입력 원문·출처 연결 보존

## 문제와 수정

추가 자료를 검토한 뒤 “필수 입력 링크는 이전 응답의 요약만 있고 이번 자료에 원문 발췌가 없다”는 이유로 조사가 중단되는 문제를 수정했습니다. 이전 병합 코드는 새 검색 자료를 먼저 배치하고 20개로 자른 뒤 모든 sourceId를 다시 만들었습니다. 입력 원문이 제외되거나, 같은 URL의 새 검색 결과가 입력 원문·입력 표시를 가리거나, 이전 factChecks의 출처 ID가 사라질 수 있었습니다. 작성·검수용 출처 필터도 factChecks에 선택되지 않은 필수 입력 자료를 제외할 수 있었습니다.

새 코드는 입력 그룹의 원문과 이전에 전달한 출처 ID를 보존합니다. 같은 URL의 다른 위치를 새로 발췌하면 이전 발췌를 덮지 않고 별도 ID로 전달합니다. 같은 내용의 중복은 줄이며, 자료 수는 기본 20개로 제한하되 필수 입력·선택 출처를 우선합니다. 보강 검토에는 앞서 주장에 연결한 출처도 전달합니다. Writer·Main에는 입력 원문과 실제 사용 출처를 함께 전달하고 무관한 자료는 제외합니다. 추가 검색 콜백과 중단 캐시를 읽는 경로에도 같은 보존 규칙을 적용합니다.

이미 이런 이유로 Research 단계에서 실패한 작업은 저장된 inputSources에 원문이 남아 있으면 복원합니다. 최초 조사·수집 자료를 재사용하고, 잘못된 자료로 받은 보강 조사 응답만 다시 검토합니다. 원래 작업 파일은 변경하지 않고 재시도 작업의 복사본을 사용합니다. 완성 원고·이미지 체크포인트를 자동 재작성하지 않습니다. 원문이 없으면 요약에서 만들어내거나 출처 검사를 생략하지 않습니다.

## 실행 방법

1. 기존 FOLAX 앱을 완전히 종료합니다.
2. FOLAX-Input-Evidence-Download.exe를 실행합니다.
3. 다운로드 폴더에서 Naver-Blog-Automator-0.3.0-rc.19.exe를 실행하고 버전을 확인합니다.
4. 작업 이력에서 이번에 실패한 해당 작업의 ‘재시도’를 한 번 누릅니다. 원문이 저장돼 있으면 “입력 원문·출처 연결 복원” 안내와 함께 수집 자료를 재사용합니다.
5. 검수 대기가 되면 원고·이미지를 확인하고 기존 승인 절차로 진행합니다.

기존 계정·설정·원고·이미지·중단 기록·승인 상태는 초기화하지 않습니다. 새 컴퓨터로의 데이터 이전은 다운로드 실행만으로 자동 이뤄지지 않습니다. 이번 배포에는 사용자 데이터나 검증용 계정·원고를 포함하지 않습니다.

Chrome 확장 0.3.22는 변경하지 않았으므로 그대로 사용합니다. 새 PC에서는 함께 제공되는 BlogAuto-Extension-0.3.22.zip을 계속 보관할 폴더에 풀어 Chrome chrome://extensions → 개발자 모드 → 압축해제된 확장 프로그램 로드에서 manifest.json이 있는 extension 폴더를 선택한 뒤 연결합니다.

## 유지되는 작성·검수 기준

새 글은 공백 제외 1,500자 목표(1,400~1,600자 허용), 태그 15개, 핵심 문장 볼드, 이미지 사용 시 기본 최소 4장, 자동 재시도 합계 최대 5회입니다. 기존 작업은 저장된 분량·태그 기준을 유지하며 티스토리에는 플랫폼 제한에 따라 앞 10개 태그를 전달합니다. 링크 전용 모드는 외부 검색을 추가하지 않습니다. 지원되지 않는 주장이나 없는 출처는 계속 반려합니다. 이 수정은 근거 전달 오류를 해결하며 자료에 없는 내용을 생성하거나 모든 글의 검수 통과를 보장하지 않습니다.

## 검증

자동 테스트 201개 통과. 자료 20개 초과 시 필수 입력 보존, 같은 URL의 다른 발췌·모바일 URL 중복, provider ID 충돌, Research·Writer·Main에 원문 전달, 기존 손상 체크포인트의 보강 검토만 재개, 출처 검사·원고·설정 보존을 검증했습니다.

격리된 실제 Electron 앱의 작업 이력 재시도 버튼으로 이전 버전에서 입력 원문이 누락된 실패 기록을 재현했습니다. 저장 원문을 복원하고 새 수집 없이 보강 Research 1회·Writer 1회·Main 1회로 검수 대기까지 진행했습니다. 각 모의 CLI 호출에서 필수 입력 원문·출처 ID가 그대로 전달되는지 검사했습니다. 본문 1,500자·태그 15개·볼드·승인 전 상태·원래 체크포인트 보존·화면 재로딩을 확인했습니다. 유료 AI 호출, 실제 계정 발행 및 Windows GUI 실행은 하지 않았습니다.

Windows x64 패키지의 소스·버전·확장 파일·네이티브 모듈을 확인하고, 공개 다운로드 파일의 크기·SHA-256과 다운로드 도우미의 파일 조합·압축 해제 결과를 검증합니다.
