# 네이버 본문 입력·정렬 오류 수정

네이버 본문 입력·가운데 정렬 수정 — 앱 0.3.0-rc.24 / Chrome 확장 0.3.23

제목과 대표 이미지만 입력된 뒤 ‘본문 정렬 버튼을 찾지 못했습니다: center’로 중단되던 오류를 수정했습니다. 저장된 원고·이미지·태그를 재사용합니다. 원고를 다시 생성할 필요가 없습니다.

업데이트와 실행
1. 기존 프로그램을 종료하고 FOLAX-Body-Alignment-Download.exe를 실행합니다. 다운로드·검증·압축 해제 후 열린 폴더에서 Naver-Blog-Automator-0.3.0-rc.24.exe를 실행합니다.
2. 이번 수정은 Chrome 확장 업데이트도 필수입니다. 프로그램의 ‘설치 폴더 준비 · 경로 복사’를 눌러 새 확장 파일을 준비합니다.
3. 해당 블로그 계정의 Chrome 창에서 chrome://extensions를 열고 BlogAuto의 새로고침(↻)을 누릅니다. 버전이 0.3.23인지 확인합니다. 다른 계정 Chrome의 새로고침은 현재 창에 적용되지 않습니다.
4. 예전에 별도로 압축을 푼 폴더에서 확장을 로드했다면, BlogAuto-Extension-0.3.23.zip의 extension 폴더 안 파일을 기존에 로드한 확장 폴더에 덮어쓴 후 새로고침하세요. 폴더 경로를 그대로 유지하면 기존 확장 연결 정보도 유지됩니다. 또는 프로그램이 준비한 폴더를 새로 로드하고 계정을 연결할 수 있습니다.
5. 원고 탭에서 기존 원고를 열어 발행 버튼을 다시 누릅니다. 저장된 본문과 이미지를 사용하여 새 글쓰기 화면에 입력합니다. 첫 이미지와 제목만 들어간 기존 열린 편집기 내용은 자동 삭제하지 않습니다.

이전에 ‘발행 결과 불확실’로 멈춘 경우
로컬 확장 기록에서 같은 계정·원고·발행 요청이 최종 발행 전 writing 단계에서 중단된 것이 명확히 확인되면 ‘입력 실패’ 상태로 바로잡습니다. 사용자 승인과 실패 사유는 보존하며 자동 재발행은 하지 않습니다. 발행 버튼을 직접 눌러 다시 입력할 수 있습니다.
기록이 없거나 발행 버튼 실행 이후의 결과는 계속 ‘불확실’로 유지합니다. 이때는 Chrome 공개·예약·임시저장 목록을 직접 확인하고, 원고 화면의 ‘Chrome에서 확인한 결과’에서 ‘미발행임을 직접 확인’을 선택해 기록한 뒤 진행하세요. 이미 발행된 원고는 중복 실행하지 않습니다.

수정 내용
- aria-haspopup 속성이 없는 정렬 메뉴, 단축키가 포함된 버튼 이름, 정렬 클래스 등 메뉴 탐색을 보강했습니다.
- 메뉴로 적용하지 못하면 실제 활성 입력 영역의 기본 정렬 명령도 사용하고 표시된 문단에서 결과를 확인합니다. 화면에 CSS만 덧씌워 성공한 것처럼 처리하지 않습니다.
- 정렬을 적용하지 못하더라도 현재 정렬로 본문 전체를 입력합니다. 정렬 미적용 안내는 작업 진행 화면과 플랫폼별 발행 기록에 표시합니다.
- 본문 누락·입력 순서·이미지 개수·AI 이미지 표시·볼드 검증은 유지합니다. 내용이 빠진 글을 정상 완료로 처리하지 않습니다.
- 최종 발행 전 확정된 입력 오류는 ‘본문 입력 중단’으로 구분합니다. 원고·이미지·승인은 보존하고, 사용자가 발행 버튼을 다시 누를 때만 입력을 시작합니다.
- 기존 계정·설정·원고·원본 체크포인트·작업 이력을 삭제하지 않습니다. 실패 원고 직접 승인 기능도 유지합니다.

검증
자동 테스트 262개 통과(신규 10개). 실제 Chromium 편집 환경에서 기본 정렬 명령, 메뉴 속성 변경, 단축키 레이블, 정렬 기능 부재의 네 경우 모두 본문 4문단·이미지 4개 자리·볼드·전체 내용 검증을 완료했습니다. 실제 앱 화면에서 이전 오류 상태 복구, 승인 유지, 명시적 재시도, 동일 본문·이미지 재사용, 서식 안내 표시와 중복 실행 차단을 확인했습니다.
이 검증에는 편집기 테스트 화면과 모의 발행 함수를 사용했습니다. 실제 네이버 편집기의 현재 화면·실제 이미지 업로드·Windows GUI 실행·실제 글 발행은 사용자 PC에서 확인해야 합니다. 이번 작업에서 실제 네이버 글을 발행하거나 유료 AI를 호출하지 않았습니다.

구현: 확장 결과 오류에는 브리지 서버의 영구 작업 단계와 작업 ID를 전달합니다. AUTHORING_FAILED + writing인 경우만 미발행 입력 오류로 분류하며 final_publish는 입력 단계로 되돌릴 수 없습니다. 과거 오류 상태 복구는 같은 계정·대상 블로그·제목·본문·공개 범위·일정·요청 시간 범위·정확한 오류 내용이 일치하는 단일 실패 기록에 한정합니다.
