# Windows 다운로드 504 복구

FOLAX 다운로드 오류 504 수정 — 새 다운로드 도구 v2

‘Downloading 1/30’에서 HTTP 504가 반복되던 다운로드 도구를 수정했습니다. FOLAX 프로그램은 Codex 설치·로그인 기능이 포함된 0.3.0-rc.25 그대로이며, Chrome 확장 0.3.23도 같은 폴더에 들어 있습니다.

사용 방법
1. 실패한 이전 다운로드 창을 닫습니다.
2. 새 FOLAX-Codex-Setup-Download-v2.exe를 실행합니다. 이전 파일과 이름 끝의 v2를 구분하세요.
3. 다운로드가 끝나면 열린 BlogAuto-Windows 폴더에서 Naver-Blog-Automator-0.3.0-rc.25.exe를 실행합니다. Chrome-Extension 폴더도 함께 준비됩니다.
4. 새 PC의 Codex 설치는 프로그램 상단 ‘Codex 설치·로그인’에서 설치 → ChatGPT 로그인 → 상태 확인 순서로 진행합니다.

수정 내용
- 504가 나면 같은 주소만 반복하지 않고 공식 GitHub 다운로드 경로와 공식 공개 API 경로를 전환합니다. 개인 GitHub 토큰은 필요 없습니다.
- curl과 PowerShell 다운로드를 번갈아 사용합니다. 요청마다 새 주소 확인값을 붙여 오래된 리디렉션이나 오류 응답을 재사용하지 않도록 했습니다.
- 파일 목록·크기·SHA-256 검증값은 다운로드 도구에 포함했습니다. 별도의 목록 파일 다운로드가 실패해 시작하지 못하는 경우를 줄였습니다.
- 파일 크기와 SHA-256이 맞는 조각만 사용합니다. API가 파일 대신 JSON 정보를 반환하거나 전송이 끊기면 해당 내용을 실행파일로 인정하지 않습니다.
- 완료된 정상 조각은 기존 다운로드 폴더에서 그대로 재사용합니다. 검증되지 않은 임시 조각만 다시 받습니다. 계정·설정·원고·작업 이력은 변경하지 않습니다.

검증
기본 경로에 504를 강제로 발생시킨 후 공식 공개 API에서 실제 첫 조각을 받아 원본 SHA-256과 일치함을 확인했습니다. 저장된 조각을 복사하지 않은 새 폴더에서 30개를 실제 네트워크로 받아 전체 ZIP 검증과 압축 해제를 완료했습니다. 이 과정에서도 실제 504가 재현됐으며 API 경로 전환으로 진행됐습니다. 자동 테스트에서는 504 전환, curl 미설치, API JSON 거부, 전송 중단, 기존 파일 보존과 고정 목록 검증을 확인했습니다.
실제 Windows GUI 실행이나 네이버 글 발행은 수행하지 않았습니다.

구현: scripts/download-windows.ps1은 내장 windows-download.json의 기존 rc.25 30개 자산 ID·URL·크기·해시를 사용합니다. Windows PowerShell 5 호환 문법을 사용하며 TLS 검증과 기존 프록시 설정을 유지합니다. 만료되는 서명 URL이나 인증 토큰을 저장하지 않습니다. 프로그램 바이너리는 재빌드하거나 교체하지 않습니다. 기존 v1 도구·공개 파일도 그대로 둡니다.
