# FOLAX 0.3.0-rc.6 — 임시저장 본문 입력·확인란·운영사 문구

## 변경

- 제목과 대표 이미지 다음에 오는 본문 입력 요소 탐색을 보강했습니다. 네이버의 `.se-component.se-text` 안에 있는 문단을 직접 찾고, 이미지 뒤에 이미 존재하는 빈 문단에 불필요한 입력 영역을 만들지 않고 이어 씁니다. 새 입력 영역을 만들지 못하면 원고와 이미지를 보존하고 구체적인 오류를 표시합니다.
- 새로 업로드한 이미지의 이름을 편집기 요소에 기록합니다. 네이버가 이미지 대체텍스트를 비우거나 바꾸더라도 앱이 업로드한 이미지를 순서대로 식별합니다. 원고·이미지 일치 검사는 유지합니다.
- 각 본문 입력의 시작·완료를 진행 로그로 표시합니다. 전체 본문·이미지·순서 검증이 끝나야 임시저장 완료로 처리하는 기존 검사는 유지합니다.
- `실제 발행 실행 확인 · 현재 제목을 정확히 입력` 입력란과 서버의 제목 재입력 요구를 제거했습니다. 승인한 원고에서 발행/저장 버튼을 누르면 됩니다. 최종 승인·이미지 확인·현재 원고 버전·중복 발행 방지는 유지합니다.
- 운영사 이름을 글 끝에 자동 추가하도록 해석될 수 있던 생성 지침을 수정했습니다. 기존 원고의 발행본에서도 요청하신 `운영: FOLAX(포렉스) / YM INTL Co., Ltd.` 마지막 문구만 제거합니다. 원래 저장한 버전은 덮어쓰지 않습니다. 실제 협찬 표시·저작권 귀속 등 다른 문구는 유지합니다.

## 설치와 재시도

1. 기존 앱을 완전히 종료하고 `FOLAX-Draft-Body-Download.exe`를 실행합니다.
2. 다운로드·체크섬 검사·압축 해제 후 `Naver-Blog-Automator-0.3.0-rc.6.exe`를 실행합니다. 도우미는 앱을 자동 실행하지 않습니다.
3. 해당 계정 Chrome의 `chrome://extensions`에서 BlogAuto를 새로고침(↻)하세요. 확장 0.3.21 / 편집기 20261028.1이 필요합니다. 계속 이전 버전이면 제공된 `BlogAuto-Extension-0.3.21.zip`을 별도 폴더에 풀고 내부 `extension` 폴더를 개발자 모드의 압축해제된 확장으로 로드·연결하세요. Chrome 로그인 프로필을 삭제할 필요가 없습니다.
4. 기존 승인 원고를 열고 공개 범위를 `네이버 임시저장`으로 선택한 뒤 `지금 임시저장`을 누르세요. 원고 재생성이나 제목 재입력은 필요하지 않습니다. 제목·이미지 뒤 각 본문 입력 시작/완료가 로그에 표시됩니다.
5. 이전 작업이 `결과 확인 필요`로 표시되면 Chrome의 임시저장/게시글 목록에서 실제 결과를 먼저 확인하고 앱의 확인 결과 기록을 사용하세요. 이미 저장한 글을 자동 중복 저장하지 않습니다.

기존 계정·설정·원고·중단 작업 이력·이미지는 초기화하지 않습니다. 1,000~1,200자 정책과 즉시/예약 발행도 유지합니다. 공개 범위가 임시저장인 원고를 공개 발행으로 바꾸지 않습니다.

## 검증 범위

자동 테스트 98개 통과. 이미지 이름 변경 대응·제목/대표 이미지 후 모든 본문 입력·운영 문구 제거와 협찬 문구 보존·기존 저장 버전 보존·제목 재입력 없이 승인 원고 발행·기존 승인/버전/중복 방지 검사를 검증했습니다.

브라우저 엔진에서 네이버와 같은 클래스 구조의 편집기를 만들어 기존 코드의 본문 위치 탐색 실패를 재현했고, 수정 후 실제 `execCommand` 본문 입력 및 대표 이미지 유지가 확인됐습니다. 실제 Electron 화면/IPC에서는 제목 입력란 제거와 임시저장 요청을 검증했습니다. 발행 함수는 모의 처리했으며 실제 외부 발행 요청·유료 AI 호출은 0건입니다.

사용자 PC 로그는 아직 제공받지 못했습니다. 로그인된 실제 네이버와 Windows GUI에서 이 중단 현상을 직접 확인한 것은 아니므로 같은 증상이 계속되면 마지막 오류 로그로 추가 진단이 필요합니다. Windows x64 EXE와 확장 파일을 빌드·포함하고 패키지 소스·버전·분할 다운로드 체크섬을 검증합니다.
