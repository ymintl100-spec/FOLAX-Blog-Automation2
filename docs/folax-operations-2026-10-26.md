## 1차: 검색 데이터와 추천 주제

### 수집 경로

1. **네이버 검색광고 API**: `/keywordstool`을 공식 API 키·Secret·Customer ID의 HMAC 서명으로 조회합니다. PC/모바일 검색수, 정확히 합산할 수 있는 통합 수치, 연관 키워드, 제공되는 월간 클릭 지표, 광고 경쟁도를 저장합니다. 광고 경쟁도는 블로그 경쟁도가 아닙니다.
2. **네이버 데이터랩 API**: 검색어 트렌드 API의 12개월 상대지수를 요청하고, 확보된 자료 안에서 1/3/6/12개월 관측값을 나눠 보여줍니다. 실제 검색 횟수로 변환하지 않습니다. 상승/유지/하락은 해당 수집 묶음의 변화 기준이며 계절형 판정에는 연속 24개월 관측이 필요합니다. 1개 관측점으로 추세를 확정하지 않습니다.
3. **CSV/XLSX 가져오기**: 키워드·추세·경쟁 분석·기존 콘텐츠·관리자 통계를 미리보기 후 저장합니다. UTF-8/UTF-16/한국어 CSV, XLSX 첫 번째 시트·공유 문자열·인라인 문자열·Excel 날짜를 지원합니다. 파일당 8MB/10,000행, 수식은 값으로 저장해야 합니다. 구형 XLS는 CSV/XLSX로 다시 저장하세요. 모든 서비스의 임의 내보내기 양식을 완벽히 자동 인식한다고 주장하지 않으며, 제공하는 빈 양식으로 정리할 수 있습니다.

`<10`은 9나 0으로 바꾸지 않고 구간으로 보존합니다. 미확인은 null, 실제 0은 0입니다. 출처·기준일·업로드 날짜·파일 해시를 저장하며 같은 파일은 중복 반영하지 않습니다. 오류 행이 있으면 부분 가져오기 없이 전체 저장을 막습니다. 같은 날의 같은 API 요청과 동시 요청은 재사용합니다. 실패 시 기존 데이터의 기준일을 바꾸지 않습니다.

### TOP 10의 의미

- 최초에는 **검색 수요 미확인 질문 제안 32개**를 제공합니다. 이를 검증된 인기 주제라고 표시하지 않습니다. 실제 검색량 자료가 없으면 TOP 10은 비어 있습니다.
- 공식 API의 연관 키워드나 가져온 검색량 자료에서 실제 확인한 후보를 추천합니다. 분류되지 않은 키워드는 브랜드 관련성 점수를 주거나 TOP 10에 넣지 않습니다.
- 핵심 키워드의 월 검색량과 제안 질문 문장 자체의 검색량을 구분합니다. 네이버 자료를 Google 검색량으로 표시하지 않습니다.
- 수요 20 / 경쟁 기회 20 / 분야 관련성 20 / 의도 15 / 독창적 설명 15 / 추세 10, 총 100점입니다. 수요는 명시된 검색량 구간의 내부 편집 점수, 분야 관련성은 사용자 분류 또는 키워드 규칙, 경쟁·의도·독창성은 실제 발췌와 판단 근거가 있는 평가만 반영합니다.
- 확인한 점수와 **평가한 배점**을 함께 표시합니다. 40점어치만 평가했으면 `점수/100 · 평가 40/100`이며 미평가를 실제 0점으로 단정하거나 100점으로 환산하지 않습니다. 신뢰 표시는 자료 충족도이지 순위·출처 진실성의 보장이 아닙니다.
- 카테고리·월 검색량·추세·질문/계절/장기 정보형·중복 필터, 점수/수요/신규 정렬, 상세 분석·선택 작성·보관·제외·복원 기능을 제공합니다.
- 경쟁 자료는 선택한 키워드만 기존 검색기로 최대 검색 2회·문서 5개, 24시간 캐시로 조회합니다. 실제 검색 결과 및 읽을 수 있는 발췌를 기록합니다. 사진·설명 깊이·검색 순위는 확인하지 못했으면 미확인입니다. 분석 점수를 적을 때 원문 발췌와 판단 근거가 필요합니다.
- 새 수집 일정은 앱이 실행 중일 때 한국 시간 기준 하루 한 번 작동합니다. 기본은 꺼짐입니다. 캐시 재사용 또는 자격 증명을 설정한 API를 선택할 수 있습니다.

## 2차: 벤치마크와 승인 편집 기준

- 2026-10-23 공개 본문 HTML에서 계측한 doctorkidney·yogawarm 100편의 주소·관찰일·구성 수치를 앱에서 볼 수 있습니다. 10월 26일에 전량 재조회한 자료로 표시하지 않습니다. 원본 화면 전체의 시각 검증을 완료한 자료도 아닙니다.

- 캡처는 로컬 등록만으로 분석 완료 처리하지 않습니다. 사용자가 선택한 캡처에 한해 Image Style 작업의 읽기 기능으로 구조 관찰을 요청할 수 있습니다. 결과는 일반적인 배치 관찰과 한계만 저장하고, 파일 해시가 같으면 재사용합니다. 실제 캡처의 유료 모델 관찰은 이 환경에서 실행하지 않았습니다.
- 타인의 원문·말투·자격·경험·사례·사진은 새 글에 복제하지 않습니다. 이미지 생성과 캡처 관찰을 구분합니다.
- 새 승인 원고는 최초 AI 원고, 수정본, 버전, 문단 차이, AI 검수, 사용자 승인/취소 날짜를 저장합니다. 이전 버전을 복원하면 새로운 수정 버전으로 만들며 이전 이력은 보존합니다.
- 수정 후 승인은 해제됩니다. 현재 버전의 AI 검수를 통과한 뒤 사용자가 다시 최종 승인해야 합니다. AI PASS만으로 사람의 승인을 대신하지 않습니다.
- 계정별 승인 프로필에는 분량·문장/줄/문단 길이·소제목·도입·마무리와 해당 승인 원고 ID/버전 근거를 연결합니다. 1개는 참고 사례, 여러 승인본의 관찰과 사용자의 명시 규칙을 구분합니다. 개별 사실·수치 수정을 일반 문체 규칙으로 만들지 않습니다.
- 우선순위: 정확성·저작권 → 사용자 필수 지침 → 승인 편집 기준 → 검색 의도 → 카테고리 → 벤치마크 → 기본 규칙. 필수 지침은 편집 프로필을 꺼도 유지됩니다.

## 3차: 승인, 부분 보완, 플랫폼별 발행

- 새 설치는 사용자 승인 모드입니다. 기존 설치의 자동 발행 설정은 읽기만 하여 보존하고 운영 화면에 이전 모드가 유지됨을 표시합니다. 사용자가 정책을 명시적으로 저장할 수 있습니다. **추천 화면에서 시작한 원고는 기존 모드와 관계없이 검수 대기로 저장**합니다.
- 선택한 주제만 수동 주제로 Research에 전달합니다. 이미지 생성은 선택 사항이며 기본은 꺼짐입니다. 필수 조건·근거를 생략해 줄이지 않고 기존 짧은 분량 정책을 유지합니다. 공개 참고자료 목록은 생략하고 내부 근거 연결은 유지합니다.
- 8개 운영 카테고리는 각기 원리/선택 기준/준비·실행/중단 조건/습관/생활 상황/연령별 조건/동일 비교 축을 강조합니다. 기존 카테고리를 덮어쓰지 않으며 누락 카테고리 추가는 사용자가 실행합니다.
- 저장한 수정본 검수는 **Main 1회**, 선택한 문단 보완은 **Writer 1회**로 수행하고 원래 조사 전체를 재실행하지 않습니다. 부분 보완 후에는 재검수가 필요합니다. 모델 오류 때 원고를 보존합니다.
- 네이버/티스토리 원고를 별도로 만들고 각각 수정·검수·승인합니다. 플랫폼 변형은 원리·구조·상황 등 전달 목적을 바꾸며 단순 동일 본문은 차단합니다. 제공 근거 밖의 심화 내용을 만들지 않습니다.
- 중복 점검은 가져온 공개/임시저장/예약/기획 콘텐츠, 로컬 원고와 계획, 작업 이력의 제목·핵심 질문을 비교합니다. 유사도는 검토 단서이며 완전한 의미 판정의 증명이 아닙니다. 접근하지 못한 관리 글 전체를 검사했다고 표시하지 않습니다. 기존 글 보강·세부 질문 분리·관련 글 연결·발행 보류 여부를 사용자가 검토합니다.
- 최종 승인 → 공개 범위/예약 발행 준비 → 제목을 입력해 실제 발행 실행 순서입니다. 이미지가 있으면 사용자의 이미지 확인이 필요하고 승인 후 파일 내용이 바뀌면 다시 승인해야 합니다.
- 플랫폼별 게시글 ID/URL/대상 블로그/원고 버전/요청·발행 또는 예약 시각을 별도 보관합니다. 임시저장·예약 등록 시점을 실제 공개된 시각으로 꾸미지 않습니다.
- 발행 중 앱 종료나 연결 단절은 `uncertain`으로 보존하고 자동 재발행하지 않습니다. Chrome의 실제 결과를 확인한 뒤 사용자 확인 기록을 남길 수 있습니다. 확인 기록도 자동 검증 결과와 구분합니다.
- 기존 공개 글을 자동 수정·삭제하거나 승인 취소로 게시글을 내리지 않습니다. 이미 확인된 발행 원고를 다시 게시하지 않습니다.

## 4차: 성과와 사용량

- 관리자 통계 CSV/XLSX를 플랫폼·지표 정의·일별/누적 기준으로 구분하여 가져옵니다. 로그인 정보를 수집하거나 통계 접근 제한을 우회하지 않습니다.
- 오늘 방문자, 7/30일 관측 평균, 최근 30일과 이전 30일, 최근 90일과 이전 90일, 게시글별 조회·검색 유입·유입 검색어·카테고리, 게시일을 포함한 7/28일 관측을 제공합니다.
- 누락한 날은 0으로 채우지 않습니다. 실제 관측 일수/필요 일수를 표시하고 불완전한 기간의 증감률을 만들지 않습니다. 플랫폼과 서로 다른 지표 정의의 방문자를 합산하지 않습니다. 누적 조회수를 일별 조회수와 더하지 않습니다.
- 추천의 성과 단서는 최근 30일 **네이버 검색 유입, 같은 지표 정의** 안에서만 사용하고 점수가 같은 후보의 검토 순서에 반영합니다. 티스토리 수치를 네이버 수치에 합치지 않으며 여섯 배점 밖의 임의 가산점을 만들지 않습니다. 새 세부 질문으로 확장할 수 있지만 같은 핵심 답을 자동 반복 발행하지 않습니다.
- 에이전트별 기록 토큰, AI 재작성, 사용자 수정, 현재 승인 비율, 승인 원고당 사용량, API 시도·오류, 작업 실패와 주간 운영 JSON 보고서를 제공합니다. 승인 비율의 분모에는 대기 원고가 포함됨을 표시합니다. 편집시간은 입력 간격을 최대 30초씩 합산한 추정값입니다.

## 테스트와 미검증 범위

자동 테스트 **78개가 통과**했습니다. CSV/XLSX·검색량 범위·캐시·서명 요청·계정 격리·DB 재시작 보존·오류 파일 보존·승인 버전·취소·현재 해시·이미지 변경·부분 보완 호출 수·플랫폼 중복·불확실 발행을 확인했습니다.

Linux Electron의 실제 창과 preload/IPC에서 6개 메뉴, 파일 선택 후 미리보기/저장, 오류 행 차단, 계정 격리, 프로필·벤치마크 저장, 최종 승인과 수정 후 무효화, 취소, 승인 없는 발행 준비 차단을 확인했습니다. 추가로 검증용 CLI를 실제 생성 실행기에 연결해 선택 주제 → Research → Writer → Main → 사용자 승인 대기 저장까지 확인했습니다. 공식 지표·AI 검수 응답은 격리된 테스트 대역을 사용했으며, 테스트 숫자와 원고는 사용자 배포 데이터가 아닙니다. **실제 유료 AI 호출 0회, 실제 게시 요청 0회**입니다.

Windows x64 파일은 빌드와 압축·패키지 소스/버전·네이티브 의존성·다운로드 해시·PowerShell 압축해제를 검사합니다. 실제 Windows에서의 GUI 실행, 실제 자격 증명을 사용한 검색광고/데이터랩 연동, 실제 유료 AI 원고·캡처 분석 품질, 로그인된 네이버·티스토리의 실제 발행·예약은 이 Linux 환경에서 확인하지 못했습니다. 이를 성공으로 보고하지 않습니다.

## 실행과 API 권한

1. `FOLAX-Operations-Download.exe` 실행으로 다운로드·검증·압축해제 후 `Downloads\BlogAuto-Windows\Naver-Blog-Automator-0.3.0-rc.1.exe`를 실행합니다. GitHub 코드 변경은 이미 설치된 EXE를 자동 갱신하지 않습니다.
2. 기존 계정을 선택하고 **검색 데이터**에서 공식 도구의 CSV/XLSX를 미리보기 후 저장합니다. 빈 양식은 앱 또는 함께 제공하는 ZIP에서 받을 수 있습니다. 검색 수요가 없으면 TOP 10이 빈 것은 정상입니다.
3. 또는 검색광고 API 관리 권한과 API Key/Secret/Customer ID, 데이터랩 검색어 트렌드 API 사용 설정이 된 Client ID/Secret을 **앱 안에서** 입력합니다. 운영체제 암호 저장소를 쓰며 평문 저장이나 채팅 입력을 요구하지 않습니다. 암호 저장소가 없으면 파일 업로드를 사용할 수 있습니다.
4. 원하는 후보 하나를 선택해 작성하고 **원고·승인·발행**에서 수정본 저장 → AI 검수 → 사용자 최종 승인 → 발행 준비 → 발행 실행합니다. 로그인은 기존 Chrome에서 직접 합니다. 티스토리 Blog ID는 기존 계정 관리에서 연결합니다.
5. 발행 후 관리자 통계를 **검색 데이터 → 관리자 통계**로 가져오고 **성과·사용량**에서 확인합니다. 네이버·티스토리·검색 엔진과 지표 정의를 섞지 마세요.

다음 실제 운영 확인은 사용자의 공식 데이터로 추천 근거를 확인하고, 원고 한 건을 수정·승인한 뒤 원하는 공개 범위로 발행하는 순서입니다. 통계 파일의 실제 열 형식이 제공 양식과 다르면 열 별칭을 추가 검토할 수 있습니다. 과거 통계·접근하지 못한 관리 글·검색 노출을 가정해서 채우지 않습니다.
