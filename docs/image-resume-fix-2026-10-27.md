# FOLAX 0.3.0-rc.3 — 이미지 스타일 보완과 출처 복원

## 확인한 원인

사용자 화면에는 서로 다른 실패가 있습니다. 먼저 대표 이미지가 생성된 뒤 실사 스타일 조건에서 반려됐습니다. 그 다음 재개에서 승인 원고의 원문 자료가 복원되지 않아 `본문 출처가 전달한 원문과 일치하지 않습니다`로 본문 품질 반려를 잘못 처리했습니다. 기존 재개 테스트는 출처를 사용하지 않는 원고여서 이 문제를 놓쳤습니다.

출처를 가진 원고로 동일한 오류를 재현했습니다. 검증을 생략하거나 출처를 창작하는 대신, 실제 저장했던 검색 자료를 복원합니다.

## 변경

- 새 이미지 체크포인트에는 당시 원문 자료와 출처 상태를 함께 저장합니다.
- 0.3.0-rc.1/rc.2 체크포인트는 같은 시도의 마지막 실제 검색 결과를 복원합니다. 다른 시도의 자료나 현재 입력으로 대체하지 않습니다.
- 이미지 재개 검증 실패는 실행 문제로 기록하고 승인 본문·체크포인트를 보존합니다. 자동으로 Writer를 다시 부르지 않습니다.
- 기존의 0토큰 출처 불일치 기록에 유효한 이미지 체크포인트가 있으면 이력 재시도에서 본문을 삭제하지 않고 이미지 단계로 복구합니다. 실제 작성·검수 품질 반려는 기존대로 처리합니다.
- 대표 이미지가 실사 스타일 조건에서 실패하면 해당 결함 설명을 보완 요청에 전달합니다. 앱이 허용한 한 번의 보완과 Worker 내부의 반복 생성 금지 지시를 구분했습니다.
- 통과한 본문 이미지는 재사용하고 실패한 이미지만 보완합니다. 실제 생성된 후보 파일은 검증 실패 시에도 경로와 실패 사유를 유지하도록 요청합니다. 실패한 검증을 통과로 바꾸거나 자동 발행하지 않습니다.

## 기존 데이터와 재개

기존 앱 ID·제품명·데이터 경로·계정·설정·원고 DB·이력 형식을 유지합니다. 초기화나 데이터 삭제는 없습니다. 실제 사용자 PC에 접근한 것은 아닙니다. 원고 재사용에는 기존 유효한 생성 체크포인트와 검색 기록이 필요합니다. 이미 삭제한 파일의 복구를 보장하지 않습니다.

1. 기존 앱을 완전히 종료합니다. 기존 작업 취소나 데이터 초기화를 누르지 마세요.
2. `FOLAX-Image-Resume-Download.exe`를 실행합니다. 다운로드 도우미는 파일을 받아 SHA-256을 확인하고 압축을 풉니다. 중단되면 도우미를 다시 실행하세요.
3. `다운로드\BlogAuto-Windows\Naver-Blog-Automator-0.3.0-rc.3.exe`를 기존과 같은 Windows 사용자로 실행합니다. 다운로드 도우미는 본 앱을 자동 실행하지 않습니다.
4. 작업 이력에서 화면의 중단 원고를 찾아 `재시도`를 누르세요. 유효한 이미지 체크포인트가 있다면 `승인된 본문과 완료된 이미지 재사용 · 미완료 이미지부터 진행`이 표시됩니다. 같은 원고의 최신 기록을 사용합니다.
5. 실제 실행 로그에서 `승인된 본문 재사용`을 확인하고 생성된 이미지와 원고를 검토하세요. 기존 계정의 발행 정책은 유지하므로 재개 전에 발행 설정을 확인하세요.

실사 스타일이나 이미지 도구의 권한·한도 문제가 계속되면 보완 한도 후 원고를 보존하고 멈춥니다. 이미지가 실제로 기준을 충족한다는 보장은 할 수 없습니다. 등록한 샘플 스타일은 삭제하거나 임의 완화하지 않았습니다.

## 검증

`npm test`: 88개 통과, 실패 0개. 출처 기반 원고의 신규·구버전 재개, 마지막 검색 결과 선택, 구버전 0토큰 출처 오류의 이력 복구, 실제 본문 품질 반려 구분, 이미지 실패 시 실행 분류, 구체적 스타일 결함 전달, 이미 통과한 이미지 보존을 추가 검증했습니다.

Windows x64 portable EXE를 빌드하고 소스·버전·Windows 네이티브 모듈·ZIP 및 분할 파일 해시를 검증합니다. 사용자 계정이나 테스트 데이터를 앱에 포함하지 않습니다. 실제 Windows GUI·실제 이미지 모델 생성·로그인 계정 발행은 이 환경에서 실행하지 않았습니다.
