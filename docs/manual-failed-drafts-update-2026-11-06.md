# 실패 원고 직접 승인·발행

실패 원고 직접 승인·발행 — 0.3.0-rc.23

생성 중 실패한 원고나 AI 검수에서 REVISION·BLOCK 판정을 받은 원고도 사용자가 직접 확인하고 승인한 뒤 발행할 수 있습니다. AI를 다시 호출하거나 AI 결과를 PASS로 바꾸지 않습니다.

사용 방법
1. 실행 중인 기존 프로그램을 종료합니다. FOLAX-Failed-Draft-Download.exe를 실행하면 다운로드·검증·압축 해제 후 폴더가 열립니다.
2. 폴더의 Naver-Blog-Automator-0.3.0-rc.23.exe를 실행하고 기존 계정을 선택합니다.
3. 원고 탭에서 기존 원고의 ‘수정·검수·발행’을 누릅니다. 생성 중 실패한 작업은 ‘실패 작업의 저장 원고’ 아래 ‘저장 원고 불러오기 · 사용 가능한 이미지만’을 누릅니다.
4. 본문·이미지·실패 사유를 확인합니다. ‘현재 버전의 사실…최종 승인’, 이미지가 있으면 이미지 확인, 그리고 ‘실패·미검수·반려 사유를 확인…’을 체크합니다.
5. ‘실패·AI 미통과 원고 직접 승인’을 누릅니다. AI 검수 결과와 사용자 직접 승인 이력은 따로 보존됩니다.
6. 공개 범위를 비공개·공개·네이버 임시저장 중 선택하고 아래 실행 버튼을 누릅니다. 직접 승인은 발행 실행과 별개입니다.

본문을 수정했다면 ‘수정본 저장’ 후 현재 버전을 다시 직접 승인하세요. AI 재검수를 실행하면 승인도 해제됩니다.

기존 데이터와 이미지
- 기존 계정·설정·원고·작업 기록·원본 체크포인트는 지우거나 덮어쓰지 않습니다. 같은 Windows 사용자 계정에서 실행하면 기존 앱 데이터 경로를 사용합니다.
- 실패 원고는 마지막으로 저장된 본문·태그·근거와 사용 가능한 이미지로 새 원고에 불러옵니다. 없는 이미지의 삽입 표식만 불러온 사본에서 제외하며, 화면에 제외 개수와 남은 이미지 수를 표시합니다.
- 같은 실패 작업을 다시 불러오면 이미 불러온 원고를 엽니다. AI 검수 반려 사유는 그대로 확인할 수 있습니다.
- 발행을 시도했거나 결과가 불확실한 작업은 새 원고로 복제하지 않습니다. 기존 발행 기록에서 결과를 확인하세요. 이미 발행된 같은 원고의 중복 실행 방지도 유지합니다.
- Chrome 확장은 0.3.22 그대로 사용합니다. 이번 수정에는 확장 교체가 필요하지 않습니다.

검증
자동 테스트 252개 통과(신규 12개). 실제 Electron 화면에서 실패 원고 불러오기, 확인 누락 차단, 사용자 직접 승인, 모의 비공개 발행, 중복 실행 차단, 새로고침 후 승인 유지, 원본 파일·작업 기록 보존을 검증했습니다. 모의 발행 함수를 사용했으며 실제 네이버 글은 발행하지 않았습니다. Windows 실행·Chrome 실발행은 사용자 PC에서 확인해야 합니다.

구현: 저장 원고의 현재 버전·본문 해시·이미지 해시와 사용자 확인을 기록합니다. 직접 승인 이벤트는 manual_override로 구분합니다. AI PASS 요건의 대안으로 명시적 사용자 직접 승인을 허용하며, 공개 범위·플랫폼·실행 중/결과 불확실/이미 발행 여부의 기존 검사는 유지합니다. 복구 사본에는 과거 AI 판정을 새 검수 결과로 부여하지 않고 원본 검수 기록으로 분리해 표시합니다. 계정별 접근·같은 재시도 계보의 멱등 복구를 적용합니다.
