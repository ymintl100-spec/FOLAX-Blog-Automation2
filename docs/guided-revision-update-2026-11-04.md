# FOLAX 0.3.0-rc.15 — 첫 작성 기준 강화·마지막 원고 이어서 보완

## 업데이트 실행

기존 앱을 완전히 종료한 뒤 `FOLAX-Smart-Revision-Download.exe`를 실행합니다. 완료되면 열린 `Downloads\BlogAuto-Windows` 폴더에서 **Naver-Blog-Automator-0.3.0-rc.15.exe**를 실행하세요. 이전 버전 EXE를 실행하면 이전 재시도 구조가 작동합니다.

Chrome 확장은 **0.3.22**를 그대로 사용합니다. 이번 업데이트에서 확장 파일은 변경하지 않았습니다. 다른 컴퓨터에서 처음 설치한다면 함께 제공되는 `BlogAuto-Extension-0.3.22.zip`을 계속 보관할 폴더에 풀고, `chrome://extensions`의 개발자 모드 → 압축해제된 확장 프로그램 로드에서 `manifest.json`이 있는 `extension` 폴더를 선택하세요. 해당 계정 Chrome을 앱과 연결하고 로그인합니다. 확장 폴더를 삭제하거나 옮기지 마세요.

## 첫 작성부터 기준을 맞추기 위한 변경

새 작업은 공백 제외 **1,000~1,500자**, 태그 **10개**, 핵심 문장 **1~3개 볼드**, 기본 이미지 **최소 4장**을 유지합니다. 키워드 1~3개·링크 1~3개·혼합 작성도 유지합니다.

Research·Writer·Main에 현재 분량과 요구사항을 명시적으로 전달합니다. Writer는 1,300자 안팎으로 여유 있게 구성하고, 한 문단마다 다른 역할을 주며 같은 동작·조건을 여러 번 해석해 늘리지 않도록 했습니다. 같은 응답 안에서 분량·핵심 답·쉬운 설명·중복·태그·이미지 계획을 점검합니다. Main은 과거 계약의 1,000~1,200자 요구를 현재 기준으로 다시 적용하지 않도록 했습니다. 별도 SEO·기획·가독성 모델을 추가하지 않습니다.

첫 원고가 통과하면 기존처럼 Research → Writer → Main으로 끝납니다. 근거가 충분하지 않으면 횟수·효과·경험을 만들어 채우거나 검수를 건너뛰지 않습니다. 내부 연관성 목표 95와 사실·의미·가독성 기준은 유지하며 점수를 임의로 올리지 않습니다. NDEX 점수나 검색 순위를 보장하지 않습니다.

## 989자 → 1,177자 사례의 처리

기존에는 989자를 보완하는 데 마지막 Writer 기회를 사용해, 이후 Main이 구체적인 품질 지침을 내도 반영할 수 없었습니다.

이번 버전은 본문·출처·이미지 계획에 다른 형식 오류가 없고 분량만 허용 범위 근처에서 벗어났다면 **아직 통과시키지 않은 상태로 내용도 함께 검수**합니다. 이후 분량과 실제 내용 지적을 **한 번의 부분 수정**에 묶습니다. 최종 분량 검사와 Main 검수를 모두 통과해야 이미지 생성으로 넘어갑니다. Main이 PASS라고 해도 글자 수가 기준 밖이면 완료하지 않습니다.

출처 누락·심한 분량 부족 등은 별도의 형식 보완 1회를 사용합니다. 내용 보완 1회와 한도를 나눠 형식 문제 때문에 내용 수정 기회가 없어지지 않게 했습니다. 원고 단계의 Writer 응답은 최초 작성을 포함해 최대 3회이며, 필요한 태그·이미지 배치 보정과 모델 실행 오류의 사용자 재시도는 기존 별도 한도를 유지합니다. 무제한 생성 반복은 하지 않습니다.

내용 보완은 원고 전체 대신 지적된 구절 최대 6개만 반환합니다. 앱이 정확한 원문 위치와 겹침을 확인해 적용하고, 제목·미수정 문단·내부 출처·소제목·이미지 번호와 순서·파일 경로를 보존합니다. 태그나 이미지 설명은 지적됐을 때만 별도로 수정합니다. 원고 위치가 맞지 않거나 표식을 바꾼 응답은 적용하지 않습니다. 부분 수정 결과에 아무 변화가 없으면 중지하고, 동일 원고·동일 지적의 같은 재시도에서 추가 모델 호출을 생략합니다.

## 이미 실패한 작업 이어가기

업데이트 후 **작업 이력 보기 → 해당 실패 작업 → 재시도**를 한 번 누르세요. 완료된 조사만 남기고 새 본문을 쓰던 방식 대신, 저장 기록이 있으면 **마지막 원고·완료된 조사·실제 Main 수정 지침**을 함께 복구합니다.

로그에서 **“마지막 원고·완료 조사·검수 지침 재사용 · 지적된 부분만 보완”**을 확인하세요. 이전 1,000~1,200자 지침은 현재 분량 정책이 1,000~1,500자인 작업에 한해 수정 요청에서 정리합니다. 기존 조사·출처 파일이나 과거 검수 결과 자체를 덮어쓰지 않습니다. 기존 작업의 태그 수·글자 수·이미지 설정·입력 목록·승인 여부는 자동 변경하지 않습니다. 이미 본문 승인을 받아 이미지 단계에서 중단된 원고는 종전처럼 본문을 재사용합니다.

통과한 원고는 **원고·승인·발행**에서 확인하세요. 검수 대기 원고를 실패로 표시하지 않으며, 이미 검수 대기 원고를 만든 작업은 이전 실패 이력에서 다시 생성하지 않습니다. 사용자 내용 확인·최종 승인 후 임시저장·즉시 발행·예약으로 진행합니다. 원고 생성과 재시도만으로 외부 게시하지 않습니다.

저장 기록이 없거나 핵심 근거 자체가 부족한 경우에는 마지막 원고를 복원하거나 반드시 한 번에 통과시킬 수 없습니다. 기존 계정·설정·원고·이미지·작업 기록을 초기화하지 않습니다.

## 확인한 범위

자동 테스트 **164개** 통과. 989자 원고의 분량·90점 품질 지침을 한 번에 보완해 1,177자와 이미지 4장 단계로 진행하는 경우, 형식/품질 보완 한도 분리, 실제 글자 수 위반의 통과 방지, 마지막 두 번째 원고·지침 복원, 잘못된 부분 수정 거절과 해당 응답만 재시도, 무변경 요청의 중복 호출 방지, 구정책 보존을 확인했습니다.

격리된 Electron 앱에서 실제 작업 이력 재시도 버튼 → 부분 Writer 1회 → Main 1회 → 사용자 검수 대기 저장을 검증했습니다. Research와 본문 전체 작성은 다시 호출하지 않았고 원본 체크포인트·제목·미수정 본문·태그·볼드는 보존했습니다. 모델은 테스트 대체 응답을 사용했으며 실제 유료 AI의 문장 품질, Windows GUI 실행, 실제 네이버 계정 발행은 검증하지 않았습니다. Windows x64 빌드·패키지 소스·다운로드 체크섬을 확인합니다.
