# FOLAX 0.3.0-rc.12 — 이미지 생성 전 검수 오류·연관 개념 표현 개선

제공된 로그에서 모델 재시도는 성공했고 본문은 939자에서 1,038자로 보완됐습니다. 이후 Main이 본문·이미지 계획은 적합하다고 하면서 아직 실행하지 않은 이미지 생성 결과를 요구해 중단했습니다. 이 검수 단계 혼동을 수정했습니다. 연관성 87점의 두 개념이 실제로 설명되지 않았는지, 다른 표현으로 설명됐는지는 사용자 원문을 받지 못해 확정하지 않았습니다.

## 수정

- Main 검수 범위를 구조화된 `text_and_image_plan` 단계로 명시합니다. 여기서 `publishable`은 본문과 이미지 계획을 다음 단계로 넘길 수 있다는 뜻입니다. 실제 이미지 생성·파일 검증·최종 승인·발행 판단은 앱의 후속 단계로 유지합니다.
- Main이 미생성 이미지 파일/결과를 요구해 반려하면 같은 본문·태그·계획·근거로 검수만 한 번 다시 요청합니다. Writer에게 이미지를 생성시키거나 본문을 그 이유로 다시 쓰게 하지 않습니다. 반복되는 잘못된 요구는 원고를 보존한 실행 오류로 중지합니다. 실제 사실·출처·본문·이미지 계획 결함은 그대로 검사합니다.
- 정상 응답에는 추가 호출이 없습니다. 잘못된 단계 요구가 있을 때만 Main 호출을 한 번 추가하며 사용량에 합산합니다. 전체 주제 재탐색·무한 재시도를 추가하지 않습니다. 기존 최대 한 차례 Writer 보완 한도를 유지합니다.
- 연관 개념의 명칭과 본문의 문자열이 달라도, 실제 본문 인용 안에 있는 표현과 개념 간 연결 설명을 함께 받아 의미를 검수합니다. 임의의 동의어 사전이나 점수 가산은 사용하지 않습니다. 인용·실제 표현·설명이 없거나 지어낸 경우는 통과시키지 않습니다. 실제 개념 누락과 키워드 나열은 기존 기준으로 반려합니다. 내부 95점 목표와 NDEX 점수 구분을 유지합니다.
- 관련 개념 상세에 실제 표현과 연결 근거를 표시합니다. 기존 저장 원고의 명시적 AI 검수도 같은 단계 계약과 한 차례 재검수 한도를 사용합니다. 원고를 자동 수정하지 않습니다.

## 이번 중단 원고 재사용

작업 이력에서 해당 실패 글의 ‘재시도’를 선택하세요. 저장된 마지막 Main 응답에 미생성 파일 요구가 확인되고 이미지 단계 이전인 경우, 연결된 마지막 Writer 원고를 가져와 본문 재작성보다 검수부터 진행합니다. 이번 경우에는 두 번째 1,038자 원고가 재사용 대상입니다. 복구 가능한 기록에서는 `마지막 본문 재사용 · 이미지 생성 전 검수 다시 확인`으로 표시합니다.

완료된 조사·검색 근거와 같은 Writer에 연결된 태그·배치·윤문 결과도 재사용합니다. 잘못된 과거 Main 판정을 승인으로 바꾸지 않고 새 기준으로 다시 검수합니다. 다른 사실·본문 품질 반려나 이미 승인된 이미지 재개 기록에는 이 복구를 강제로 적용하지 않습니다. 원본 작업 파일과 설정은 변경하지 않고 새 재시도 기록을 만듭니다. 복구할 파일이 남아 있어야 합니다.

실제 설명이 부족하면 기존 자료 안에서 보완이 필요할 수 있습니다. 95점 기준을 낮추거나 실제 이미지 4장이 없어도 발행하도록 바꾼 것은 아닙니다. 최종 본문 검수 뒤 Image Worker가 대표 1장과 본문 3장 이상을 생성하고 앱이 실제 경로·개수·확인 결과를 검사합니다. 이미지 생성 실패는 본문을 보존하고 발행을 중지합니다.

기존 계정·설정·원고·이미지·중단 작업 기록을 삭제하거나 초기화하지 않습니다. 본문 1,000~1,200자·태그 30개·이미지 최소 4장·기존 승인 절차·상세 분석 창 수정은 유지합니다.

## 실행

1. 기존 프로그램을 완전히 종료합니다.
2. `FOLAX-Review-Stage-Download.exe` 다운로드 도우미를 실행합니다.
3. `다운로드\BlogAuto-Windows\Naver-Blog-Automator-0.3.0-rc.12.exe`를 실행합니다.
4. 작업 이력에서 이번 실패 원고의 ‘재시도’를 누릅니다. 기존 작업 취소나 새 주제 선택보다 저장 원고 재개를 먼저 사용하세요.

Chrome 확장 0.3.21은 변경하지 않았습니다. 이미 해당 버전이면 다시 갱신할 필요가 없습니다. 도우미는 파일 검증과 압축 해제 후 폴더를 열며 앱을 자동 실행하지 않습니다.

## 검증

자동 테스트 139개 통과. 939자→1,038자 보완 후 잘못된 이미지 파일 요구를 Main만 재검수하고 같은 본문·태그 30개를 보존한 채 서로 다른 실제 이미지 경로 4개를 생성하는 흐름을 테스트했습니다. 모델·이미지 응답은 테스트용 대체 응답이며 실제 이미지 품질을 확인한 것은 아닙니다.

검수의 생성 결과 요구와 실제 계획 누락·사실 오류 구분, 반복되는 단계 오류 중지 및 실패한 검수만 재개, 실제 이미지 생성 실패 시 발행 중지, 원본 파일/설정 보존과 마지막 Writer/수집 근거 복구, 실제 표현 기반 의미 연결과 가짜 인용 거절을 검증했습니다. 격리된 Electron UI에서 단계 오류 뒤 한 차례 재검수, 실제 표현·연결 근거 표시, 수정 시 오래된 점수 숨김과 렌더러 오류 0건을 확인했습니다.

사용자 PC의 실제 1,038자 본문과 원시 결과 JSON은 제공받지 못했습니다. 실제 유료 AI·로그인 계정 발행·Windows GUI 실행을 수행하지 않았습니다. Windows x64 빌드·패키지 소스·버전·다운로드 체크섬을 확인합니다.
