# FOLAX 0.3.0-rc.8 — 이미지 번호·마커 오류

## 이번 오류와 변경

사용자 로그는 1차 1,080자·2차 1,072자 원고가 이미지 번호/마커 검사에서 연속 중단됐음을 보여줍니다. 이전 검사는 중복 번호·누락·표기 차이를 같은 오류로 묶고 본문 전체를 한 번 더 쓰게 했습니다. 사용자 PC의 실제 agent-result.json은 제공받지 못해 정확히 어떤 번호·표기가 잘못됐는지까지 직접 확인한 것은 아닙니다.

- 앱에서 마커의 들여쓰기·대소문자·공백·줄바꿈·유니코드 대시/숫자를 정리합니다. 이미지 계획과 마커가 일대일로 연결되면 연결을 유지한 채 1부터 번호를 정리합니다. 본문 문장·제목·출처·이미지 설명은 변경하지 않습니다.
- 글의 줄바꿈 조정 과정에서 들여쓴 마커가 일반 문장처럼 줄바꿈되지 않도록 보호합니다.
- 중복·누락으로 연결이 모호하면 본문을 다시 쓰지 않고 한 번의 이미지 배치 전용 보완을 요청합니다. AI는 기존 이미지마다 원고에 이미 있는 문단 ID만 선택합니다. 앱이 마커와 번호를 삽입하며 이미지 설명·문장·출처는 그대로 유지합니다. 원고 지문, 모든 이미지의 일대일 매핑, 실제 문단 ID와 부모 소제목을 검사합니다.
- 존재하지 않는 문단·잘못된 지문·누락된 배치를 받으면 자동 발행하지 않고 원고와 체크포인트를 보존합니다. 재시도에서는 완료된 조사·본문을 재사용하고 실패한 이미지 배치 단계만 다시 요청합니다.
- 최종 사실·독자 유용성 검수와 총 최소 4장 검사는 유지합니다. 대표 이미지는 본문 bodyImages/마커에 포함하지 않는다고 생성 지침을 명시했습니다. 실패 시 계획 번호와 본문 번호를 따로 표시합니다.
- 이미지 배치 보완의 사용량은 Writer 토큰에 실제 합산하지만 본문 재작성 횟수로 계산하지 않습니다.

## 기존에 실패한 원고 재사용

구버전에서 이 이미지 번호 오류로 실패한 작업은 이력 재시도 시 마지막으로 저장된 Writer 원고를 가져옵니다. 첫 원고로 되돌리거나 본문 전체를 새로 생성하지 않습니다. 완료된 조사와 검색 결과도 재사용합니다. 이전 원고의 검수 결과를 다른 원고에 재사용하지 않으며 새 배치 뒤에는 최종 검수를 수행합니다.

기존 계정·설정·원고·이력·이미지·체크포인트 파일은 삭제·초기화하거나 덮어쓰지 않습니다. 복구할 작업 파일이 남아 있어야 합니다. 실제 본문·근거 품질 반려는 이미지 오류로 우회하지 않습니다.

## 실행

1. 기존 앱을 완전히 종료하고 `FOLAX-Image-Marker-Download.exe`를 실행합니다.
2. 다운로드·체크섬 검사·압축 해제 후 `다운로드\BlogAuto-Windows\Naver-Blog-Automator-0.3.0-rc.8.exe`를 실행합니다. 도우미는 앱을 자동 실행하지 않습니다.
3. 작업 이력에서 이번에 이미지 번호 오류로 실패한 글의 `재시도`를 누르세요. 복구 가능한 경우 `마지막 본문 재사용 · 이미지 배치만 보완`으로 표시합니다. 기존 작업 취소나 원고 재생성은 필요하지 않습니다.
4. 로그에서 마커 정리 또는 `본문 문장 보존 · 이미지 배치만 보완`을 확인하세요. 본문 검수와 이미지 생성이 완료된 뒤 기존 승인·임시저장/발행 절차를 사용합니다.

이번 수정은 앱의 생성·배치 규칙 변경입니다. 확장이 이미 0.3.21이면 갱신할 필요가 없습니다. 1,000~1,200자, 이미지 최소 4장, 제목 재입력란 제거, 운영사 문구 제거, 임시저장 보완은 유지합니다.

## 검증

자동 테스트 109개 통과. 마커 표기 변형/0부터 시작하는 번호·중복 계획·유효한 문단 배치·잘못된 배치 응답 거절·본문/출처/제목 보존·구버전의 마지막 저장 원고 복구·전체 본문 재작성 없는 이미지 배치 보완 및 실패 후 재개를 검증했습니다. 1,000~1,200자·최소 4장 검사도 유지합니다.

모델 응답은 로컬 fixture로 검증했습니다. 실제 유료 AI 호출·Windows GUI·로그인 계정 발행은 실행하지 않았습니다. Windows x64 EXE를 빌드하고 패키지 소스·버전·다운로드 체크섬을 검증합니다.
