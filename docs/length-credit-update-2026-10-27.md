# FOLAX 0.3.0-rc.4 — 상단 표기 삭제·본문 1,000~1,200자

프로그램 상단의 `by @복사장의생존발악` 표기를 제거했습니다. 앱 이름과 버전은 표시합니다.

새 글은 공백 제외 1,000~1,200자(목표 1,100자)로 작성하고 실제 글자수를 검사합니다. 건강 설명·실행·비교·일상 및 벤치마킹 끄기에도 동일하며, 과거 승인 예시의 분량이 더 짧아도 현재 범위를 우선합니다. 문체·문단 리듬과 사실·경험의 근거는 유지합니다. 소제목과 링크 표시 문구는 포함하고 제목·이미지 표식·참고자료·URL은 글자수에서 제외합니다. 네이버·티스토리 별도 원고 생성도 같은 기준입니다. 허구나 반복으로 분량을 채우지 않습니다.

새 분량 기준은 체크포인트에 저장합니다. 기존 중단 원고·저장 원고는 원래 분량과 검수 기준을 유지하며, 업데이트 때문에 본문을 다시 작성하지 않습니다. 계정·설정·원고·이력·이미지 데이터 경로 및 형식은 유지하고 초기화나 데이터 삭제는 하지 않습니다. 이미지 재개 출처 복원과 스타일 보완 수정도 포함합니다.

## 실행

1. 기존 프로그램을 완전히 종료하세요.
2. `FOLAX-Length-Update-Download.exe`를 실행하면 다운로드·체크섬 검증·압축 해제 후 폴더가 열립니다. 중단되면 같은 도우미를 다시 실행하세요.
3. `다운로드\BlogAuto-Windows\Naver-Blog-Automator-0.3.0-rc.4.exe`를 기존과 같은 Windows 사용자로 실행하세요. 도우미는 본 프로그램을 자동 실행하지 않습니다.
4. 새 글부터 1,000~1,200자 기준이 적용됩니다. 기존 중단 글은 작업 이력의 재시도를 사용하며 원래 본문을 유지합니다. 기존 작업 취소나 데이터 초기화는 필요하지 않습니다.

## 검증

자동 테스트 90개 통과. 분량 경계(999/1,000/1,200/1,201자), 모든 형식 및 승인 예시 우선순위, 조사·작성·검수 프롬프트의 일치, 신규 정책 체크포인트와 구버전 재개, 플랫폼별 독립 원고를 검증했습니다. Linux Electron 화면에서 상단 표기 삭제와 분량 안내·앱 버전을 확인했습니다. Windows x64 EXE를 빌드하고 패키지 소스·버전·네이티브 모듈·ZIP·분할 다운로드 체크섬을 검증합니다. 실제 Windows GUI와 유료 AI 생성·발행은 이 환경에서 실행하지 않았습니다.
