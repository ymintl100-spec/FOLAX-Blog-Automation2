# rc.24 문단 수정 한도 수정

rc.24 본문 부분 수정 한도 오류 패치 — 수정본 0.3.0-rc.24.1

사용 중인 Naver-Blog-Automator-0.3.0-rc.24.exe를 기준으로 수정했습니다. 로그의 ‘7개 문단 수정이 필요하지만 한도는 6개’ 충돌을 해결합니다.

원인과 변경
기존 코드의 작성 지침과 응답 검사 양쪽이 부분 수정을 최대 6개로 제한했습니다. 여러 문단을 합칠 때 수정·삭제 각각을 세므로 실제 필요한 일곱 번째 수정이 거부됐습니다. 이번에는 현재 원고의 수정 가능한 문단 수로 상한을 정합니다. 예를 들어 수정 가능한 문단이 36개라면 그 범위 안에서 필요한 7개를 한 응답으로 보완할 수 있습니다.
모델이 과거 6개 제한을 다시 적용해 수정 불가라고 응답하면 같은 원고를 유지하며 남은 자동 보완 한도 안에서 다시 요청합니다. 이런 개수 제한 충돌은 근거 부족과 구분해 불필요한 검색을 하지 않습니다. 전체 재시도는 기존대로 합계 최대 5회이며, 원고 식별 불일치·잘못된 문단 ID·소제목/이미지 표식 변경·사실 검수 차단은 그대로 적용합니다. 글자 수 1400~1600자, 태그 15개, 이미지 계획과 승인 절차는 유지합니다.

작은 패치 사용 방법
1. 기존 FOLAX 프로그램을 완전히 종료하세요.
2. FOLAX-rc24-Revision-Patch.exe를 다운로드하고 실행합니다. 약 165KB이며, 패치 실행 중 인터넷에서 추가 파일을 내려받지 않습니다.
3. 파일 선택창에서 현재 사용 중인 Naver-Blog-Automator-0.3.0-rc.24.exe를 선택합니다. 다운로드용 FOLAX-...-Download.exe가 아니라 실제 프로그램 파일을 선택하세요.
4. 새 Naver-Blog-Automator-0.3.0-rc.24.1.exe를 저장할 위치를 확인합니다. 원본은 덮어쓰지 않습니다.
5. 완료 후 열린 폴더의 새 rc.24.1 실행파일을 실행하세요. 원본 rc.24도 그대로 남아 있습니다.
6. 작업 이력에서 중단된 원고의 ‘재시도’를 누르면 저장된 조사·마지막 원고·검수 지침을 재사용합니다. 수정할 부분만 보완하며 처음부터 글을 만들 필요가 없습니다.

원본 파일이 일치하지 않는다고 나오면
이 패치는 앞서 제공한 공식 rc.24 실행파일을 대상으로 합니다. 다른 버전이나 다운로드 도구를 선택하면 검증에 실패하며 어떤 원본 파일도 변경하지 않습니다. 정확한 rc.24 파일을 다시 선택하세요.

보존되는 항목
기존 계정·설정·원고·이미지·중단 기록·Chrome 확장 연결은 그대로 사용합니다. rc.25의 Codex 설치 기능이나 새 다운로드 도구를 추가하는 업데이트가 아닙니다. Chrome 확장 0.3.23도 그대로 사용합니다.

검증
rc.24 기준 자동 테스트 274개 통과(본문 한도 회귀 7개와 안전한 패치 적용 5개 추가). 실제 Electron 화면에서 저장된 36문단 원고의 7문단을 한 번에 보완하고, 조사·본문 전체 생성 없이 재검수 대기까지 진행함을 확인했습니다. 테스트 원고는 1529자·태그 15개이며 원본 체크포인트와 이전 실패 기록을 보존했습니다. 이력의 수동 재시도는 기존 규칙대로 새 5회 회차를 시작하며 이전 회차 기록을 보존합니다.
공식 rc.24 실행파일에 실제 패치를 적용해 빌드한 rc.24.1 실행파일과 SHA-256이 일치함을 확인했습니다. 잘못된 원본·변조된 패치·범위를 벗어난 복사·다른 기존 대상 파일은 변경하지 않고 거부하는 테스트를 통과했습니다.
AI 응답은 모의 응답을 사용했습니다. 실제 AI 글 생성, Windows GUI의 파일 선택창 조작과 네이버 발행은 수행하지 않았습니다.

기반 커밋: 7e8b0615a172541bf14f544535240acaf28e3b8a. 수정된 앱 파일은 editorialRevision.js, revisionEvidence.js 및 버전 표시입니다. 패치 도구는 COPY/LITERAL 조각으로 별도 파일을 구성한 후 전체 대상 해시를 검증합니다. 원본 EXE나 앱 사용자 데이터 파일을 쓰기 모드로 열지 않습니다.
