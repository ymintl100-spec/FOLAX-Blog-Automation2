# FOLAX 0.3.0-rc.16 — 1,500자·태그 15개·자동 재시도 최대 5회

## 업데이트 실행

기존 앱을 완전히 종료하고 `FOLAX-Auto-Retry-Download.exe`를 실행합니다. 다운로드가 끝나면 열린 폴더에서 **Naver-Blog-Automator-0.3.0-rc.16.exe**를 실행하세요. 이전 버전 EXE에서는 새 기준이 적용되지 않습니다.

Chrome 확장은 **0.3.22**를 그대로 사용합니다. 이번 업데이트에서 확장 소스는 변경하지 않았습니다. 새 컴퓨터에서는 함께 제공된 `BlogAuto-Extension-0.3.22.zip`을 계속 보관할 폴더에 풀고, Chrome `chrome://extensions` → 개발자 모드 → 압축해제된 확장 프로그램 로드에서 `manifest.json`이 있는 `extension` 폴더를 선택합니다. 해당 Chrome을 앱과 연결하고 로그인하세요. 확장 폴더를 삭제하거나 옮기지 마세요.

## 새 글 기준

- 본문은 **공백 제외 1,500자 목표**, **1,400~1,600자 허용**입니다. 제목·참고자료·이미지 표식·URL은 제외하고 소제목과 링크 표시 문구는 포함합니다.
- 주제와 실제 본문에 맞는 태그 **15개**를 별도 저장합니다. 네이버에는 15개를 전달합니다. 티스토리는 플랫폼 제한에 따라 앞 10개를 전달합니다.
- 핵심 문장 볼드, 기본 이미지 최소 4장, 키워드 3칸·링크 3칸·혼합 작성, 쉬운 문장 기준과 사용자 수정·승인 흐름을 유지합니다.
- 사실·조건·의미·내부 연관성 목표 95를 낮추거나, 태그·키워드·허구의 경험으로 분량과 점수를 채우지 않습니다.

새 기준은 새 글 작성에 적용합니다. 기존 계정·설정·원고·이미지·승인·중단 기록은 초기화하지 않습니다. 저장 원고나 중단 원고의 기존 분량·태그 설정은 보존하며 자동으로 다시 쓰지 않습니다.

## 자동 재시도 5회의 의미

**최초 작성은 재시도에 포함하지 않습니다.** 한 작업의 자동 재시도는 합계 최대 **5회**입니다. 예를 들어 최초 원고가 반려되고 5번의 부분 보완까지 사용하면 원고 작성/보완은 최대 6번입니다. 기준을 충족하면 남은 횟수를 사용하지 않고 즉시 다음 단계로 넘어갑니다.

분량·가독성·본문 품질 보완, 태그/이미지 배치 보완, 잘못된 검수 응답 보완, 일시적인 텍스트 모델 응답 오류, 모델 호환 재시도, 미완료 이미지의 확인 가능한 보완은 **같은 5회 한도**를 사용합니다. 각 보완 뒤 필요한 검수는 그 보완의 확인 단계입니다. 정상적인 조사·자료 보강과 최초 이미지 생성은 기본 작업 단계이며, 재시도 횟수와 AI 호출 총횟수는 서로 다릅니다.

조사와 마지막 원고를 재사용해 지적된 부분만 수정하며, 주제를 바꿔 전체 생성 파이프라인을 반복하지 않습니다. 잘못된 부분 수정 응답이나 실제 변경이 없는 응답도 마지막 원고를 보존하고 같은 한도 안에서 자동 보완합니다. 5회를 사용해도 기준에 미달하면 마지막 원고와 지침을 보존하고 중지합니다. 남은 횟수를 이유로 사실 검수를 건너뛰거나 자동으로 통과시키지 않습니다.

로그인·인증·사용 한도 문제, 원문을 읽을 수 없는 링크, 근거가 없어 고칠 수 없는 핵심 주장 BLOCK은 반복 호출로 해결하지 않습니다. 이미지 생성 실행이 끊겨 이미 파일을 만들었는지 불확실한 경우에도 무작정 재실행하지 않고 저장 내용을 보존합니다. 실제 발행 요청은 자동 재시도 대상으로 삼지 않아 중복 게시를 방지합니다.

## 횟수 확인

앱 **상단**에 `자동 재시도 0/5`와 진행 막대가 표시됩니다. 실제 재시도가 시작될 때 `1/5`, `2/5` … `5/5`로 바뀝니다. 로그에는 단계 이름도 표시됩니다.

작업 이력과 저장 원고에도 사용 횟수를 표시합니다. 화면 새로고침이나 앱 재시작으로 횟수를 초기화하지 않으며 중단 기록의 사용 횟수를 이어갑니다. 기존 버전의 중단 작업을 새 버전에서 재개할 때는 분량·태그를 바꾸지 않고 새 자동 재시도 한도만 적용합니다.

사용자가 **작업 이력 → 재시도**를 직접 누르면 이전 기록을 남긴 채 새 회차를 시작하고 그 회차에서 최대 5회까지 자동 보완합니다. 이것은 앱이 몰래 한도를 초기화하는 동작이 아닙니다. 이미 검수 대기 원고가 저장된 작업은 이전 실패 이력에서 다시 생성하지 않습니다.

## 완료 후

**원고·승인·발행**에서 본문·태그·이미지를 확인하고 현재 버전을 최종 승인합니다. 이후 임시저장·즉시 발행·예약을 선택하세요. 자동 재시도만으로 외부 게시하지 않습니다.

## 확인한 범위

자동 테스트 **181개** 통과. 첫 작성 통과 시 0회, 1회 보완 후 조기 종료, 5번째 보완에서 통과, 계속 반려될 때 5회 정지, 잘못된/무변경 응답의 부분 재시도, 태그/품질/응답 오류의 한도 공유, 횟수의 저장·재개, 기존 분량·태그 보존을 확인했습니다. 보고된 실패 호출 사용량도 재시도 결과에 합산합니다.

격리된 Electron 앱에서 최초 원고 작성 1회 → 부분 보완 5회 → 검수 대기 저장을 실제 버튼 경로로 검증했습니다. 상단 횟수·진행 막대가 0→5로 바뀌고, 작업 이력과 원고에 횟수가 저장되며 화면 새로고침 후에도 5/5를 유지했습니다. 저장 원고는 공백 제외 1,500자·태그 15개·볼드를 확인했고 최종 승인은 대기 상태입니다. 모델은 테스트 대체 응답을 사용했으며 실제 유료 AI의 문장 품질, Windows GUI 실행, 네이버 실계정 발행은 검증하지 않았습니다. Windows x64 빌드·패키지 소스·다운로드 체크섬을 검증합니다.
