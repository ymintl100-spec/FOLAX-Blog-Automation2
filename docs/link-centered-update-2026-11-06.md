# FOLAX 0.3.0-rc.20 — 입력 링크 중심 작성·키워드 보충 검색

## 작성 방식 변경

키워드 + 링크 혼합 작성은 입력 링크의 실제 주제·대상·사용 목적·핵심 내용을 중심으로 비슷한 범위의 새 글을 작성합니다. 원문의 문장·개인 경험·사진을 복제하지 않으며, 검색한 다른 자료가 글의 중심 주제를 바꾸지 않게 합니다. 키워드는 원문과의 관련성을 분석하고 부족한 설명을 찾는 검색어로 사용합니다.

예를 들어 입력 글이 지압매트의 사용 방법과 편안한 강도를 설명하면 그 도구와 사용 상황을 중심으로 기획합니다. 이를 ‘모든 발바닥 자가 지압의 통증·중단 기준’이라는 새 임상 주장으로 넓힌 뒤, 새 주장의 근거가 없다는 이유로 계속 검색하지 않도록 했습니다. 링크의 핵심 내용 자체가 잘못됐거나 근거가 없다면 통과시키지 않습니다. 실제 의학적 주장·위험·조건·불확실성은 보존하고 검수합니다.

## 자료 수집과 기획

혼합 방식에서는 링크를 먼저 읽습니다. 원문에 필요한 내용이 충분하면 별도 키워드 검색 없이 Research → Writer → Main으로 작성합니다. 부족한 항목이 있을 때만 같은 Research 응답에 입력 키워드와 구체적인 보충 질문을 기록하고, 앱이 ‘입력 키워드 + 링크의 대상 + 질문’으로 웹에서 자료를 수집합니다. 검색어는 실제 검색 길이 제한 안에서 만들며, 기존 제목에서 임의로 넓어진 임상 검색어를 그대로 사용하지 않습니다. 조회한 자료는 대상·환경·목적이 맞는 범위에서만 사용합니다. 검색 결과와 원문 발췌의 출처 ID를 보존합니다.

Research는 모든 입력 링크 각각의 주제·사용 목적·실제 원문 구절을 linkScope로 연결합니다. Writer와 Main은 같은 기획과 원문을 전달받습니다. Main은 생성한 제목과 본문만 대조하지 않고 원래 링크의 범위도 검사합니다. PASS에는 실제 원문과 실제 원고의 짧은 구절이 필요하며, 없는 구절이나 출처 ID는 응답 보완 대상으로 처리합니다. 잘못된 일반화·과장·주제 이탈은 기존 Writer 보완으로 수정합니다.

보강 자료로도 넓어진 주장을 뒷받침하지 못하면 기존 조사 안에서 한 차례 원문 범위로 기획을 재조정합니다. 지원되지 않는 확장 주장은 제목·계약·factChecks에서 함께 제외하도록 합니다. 추가 검색이나 별도 에이전트를 늘리지 않으며, 이 조정과 응답 보완도 기존 자동 재시도 합계 최대 5회에 포함됩니다. 실제 핵심 근거 부족·중복 발행 주제·원문 읽기 실패는 그대로 중단합니다. 무조건 검수 통과를 보장하는 변경은 아닙니다.

## 기존 실패 작업 재시도

1. 기존 FOLAX 앱을 완전히 종료합니다.
2. FOLAX-Link-Centered-Download.exe를 실행합니다.
3. 다운로드 폴더의 Naver-Blog-Automator-0.3.0-rc.20.exe를 실행하고 버전을 확인합니다.
4. 작업 이력에서 이번 Research 실패 작업의 ‘재시도’를 한 번 누릅니다.
5. ‘입력 링크 주제 중심으로 기획 재검토 · 저장 자료 재사용’ 안내를 확인합니다. 저장된 원문과 수집 자료는 유지하고, 이전에 넓어진 제목·기획을 다시 판단합니다.
6. 검수 대기가 되면 원고·이미지를 직접 확인하고 기존 승인 절차로 진행합니다.

저장된 혼합 작성 작업이 Research 단계에서 실패했고 원문 캐시가 남아 있는 경우에 적용합니다. 완성 원고·이미지 체크포인트·승인 상태는 새 기획으로 자동 재작성하지 않습니다. 원래 작업 파일은 변경하지 않고 재시도 작업 복사본을 사용합니다. 키워드만 작성하는 방식과 외부 검색을 하지 않는 링크 전용 방식은 기존 동작을 유지합니다.

새 글은 공백 제외 1,500자 목표(1,400~1,600자 허용), 태그 15개, 핵심 문장 볼드, 이미지 사용 시 기본 최소 4장, 자동 재시도 최대 5회를 유지합니다. 기존 작업의 분량·태그는 저장된 기준을 따르며 티스토리에는 플랫폼 제한에 따라 앞 10개 태그를 전달합니다.

기존 계정·설정·원고·이미지·작업 이력을 초기화하지 않습니다. 배포 파일에 사용자 데이터는 포함하지 않습니다. Chrome 확장 0.3.22는 변경하지 않았으므로 그대로 사용합니다. 새 PC는 함께 제공되는 BlogAuto-Extension-0.3.22.zip을 계속 보관할 폴더에 풀고 chrome://extensions → 개발자 모드 → 압축해제된 확장 프로그램 로드에서 manifest.json이 있는 extension 폴더를 선택한 뒤 연결합니다. 프로그램 다운로드만으로 기존 PC의 계정 데이터가 자동 이전되지는 않습니다.

## 검증 범위

자동 테스트 217개 통과. 충분한 원문에서 검색 생략, 부족한 항목만 입력 키워드로 검색, 넓어진 주장에 대한 한 차례 범위 재조정, 여전히 부족한 핵심은 중단, 실제 원문·원고 구절 검증, 원문 범위 이탈 반려, 잘못된 응답만 보완, 다중 링크·키워드, 검색어 길이, 중복 발행 방지, 기존 원고·설정·이미지 재개를 확인했습니다.

격리된 실제 Electron 앱의 작업 이력 버튼으로 이전 버전에서 넓어진 임상 주장 때문에 실패한 기록을 재현했습니다. 저장된 입력 원문과 다른 환경의 수집 자료를 유지하고, 이전 기획을 재사용하지 않고 링크 중심으로 다시 기획했습니다. 실제 Main의 검색 콜백에서 입력 키워드·링크 대상·부족한 질문으로 웹 검색을 요청하는지 검사했습니다. 모의 검색 응답 1회와 모의 Research 2회·Writer 1회·Main 1회로 검수 대기까지 진행했습니다. 원문 전달, linkScope 인계, 본문 1,500자·태그 15개·볼드·승인 전 상태·원래 체크포인트 보존·작성 안내·새로고침을 확인했습니다. 유료 AI, 실제 검색 사이트 수집, 실제 계정 발행 및 Windows GUI 실행은 수행하지 않았습니다.

Windows x64 패키지의 소스·버전·확장·네이티브 모듈을 확인하고, 공개 다운로드 파일의 크기·SHA-256과 다운로드 도우미의 파일 조합·압축 해제 결과를 검증합니다.
