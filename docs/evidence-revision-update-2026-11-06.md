# FOLAX 0.3.0-rc.22 — 본문 부족 자료 보강·자동 보완 흐름 수정

## 왜 2/5에서 중단됐는가

이전 ‘전체 1회 시도 소진’의 1회는 주제를 처음부터 다시 생성하는 전체 흐름 한도였고, 본문 자동 재시도 5회와는 별도였습니다. Writer가 반복 제거와 최소 분량을 동시에 충족할 수 없다며 status:failed를 반환하면, 이전 코드는 이를 즉시 중단했습니다. 본문 보완 중에는 추가 자료를 검색하는 경로도 없었습니다.

새 버전은 키워드가 있는 작업의 분량·근거 부족을 키워드 자료 보강 → 기존 Research의 새 자료 판정 → 저장 원고의 필요한 문단 보완으로 이어갑니다. 주제 전체를 다른 소재로 다시 생성하지 않으며, 같은 문장을 반복하거나 사실·효과·경험을 만들어 분량을 채우지 않습니다. 짧은 첫 초안과 첫 작성의 근거 부족도 보강 대상으로 처리합니다.

## 자동 보완과 자료 검수

본문 수정과 키워드 자료 보강은 같은 합계 최대 5회 예산을 사용하고 상단·작업 이력에 실제 사용 횟수를 표시합니다. 예를 들어 본문 수정 2회 뒤 자료 보강 1회, 다시 본문 수정 1회를 하면 4/5입니다. 보강 1회에는 검색과 해당 자료를 읽는 기존 Research 검토가 함께 들어갑니다. 새 검수 에이전트나 별도 SEO 호출을 추가하지 않습니다. 정상 완료되면 5회를 모두 쓰기 전에 마칩니다.

검토된 새 사실과 허용된 실제 sourceId·URL을 Writer에게 명시적으로 넘깁니다. 새 자료를 받았어도 옛 원문만 사용할 수 있다고 해석하지 않게 했습니다. 실제 사용한 새 출처만 내부 citations에 추가하며 기존 출처·제목·소제목·이미지 마커·파일 경로를 유지합니다. sourceId나 URL이 다르거나 원문에 없는 인용이면 거부합니다. 새 자료의 대상·조건·불확실성은 보존하고 원래 링크 주제를 벗어난 주장으로 확장하지 않습니다. 최종 Main의 사실성·가독성·원문 범위·연관성 검사는 그대로 유지합니다.

원문을 찾지 못하거나 원고에 쓸 수 없는 자료이면 서로 다른 보충 질문으로 남은 횟수 안에서 확인합니다. 쓸 자료가 없을 때 같은 유료 Writer 호출을 반복하지 않습니다. 본문 보완용으로 작업당 추가 검색 요청 최대 10회·새 원문 최대 12개의 제한된 별도 수집 예산을 마련하고 기존 검색·원문 캐시를 공유합니다. 초기 조사 예산 소진 때문에 보완 검색이 바로 막히지 않도록 했습니다. 자동 보완 5회에 도달하면 마지막 원고·검수 지침·수집 자료를 보존합니다. 취소·인증/사용 한도·원고 식별/출처 검증 오류·실제 최종 BLOCK 등은 별도 중단 사유이며, 검수 통과를 강제하거나 횟수만 채우려고 호출하지 않습니다.

‘전체 1회 소진’ 대신 ‘작업 보완 중단 · 자동 재시도 N/5 사용’과 실제 원인을 표시합니다. 작업 이력 상세도 전체 흐름 횟수와 자동 보완 횟수를 혼동하지 않게 표시합니다.

## 링크와 비슷한 제목·글

새로 읽는 블로그 링크는 임시 이름 ‘입력 링크 원문’ 대신 실제 HTML/OG 제목을 추출해 전달합니다. 혼합 작성에서는 실제 제목의 핵심어·원문의 주제·설명 순서·소제목 의미를 참고해 새 문장으로 작성합니다. 방법 소개를 임의의 필요성 찬반이나 새로운 임상 질문으로 바꾸지 않도록 기획 지침을 강화했습니다. 저장된 기존 원고는 제목과 내용을 임의로 바꾸지 않고 마지막 원고부터 보완합니다. 실제 제목을 확보하지 못했으면 안다고 가장하지 않습니다.

## 실행·중단 작업 재사용

1. 기존 FOLAX 앱을 완전히 종료합니다.
2. FOLAX-Evidence-Revision-Download.exe를 실행합니다.
3. 다운로드 폴더에서 Naver-Blog-Automator-0.3.0-rc.22.exe를 실행하고 버전을 확인합니다.
4. 작업 이력에서 이번에 실패한 해당 작업의 ‘재시도’를 한 번 누릅니다.
5. 마지막 1,488자 원고와 검수 지침·완료 조사를 재사용해 필요한 보완부터 진행합니다. 수동 재시도는 새 5회 라운드를 시작하며 이전 라운드의 사용 기록은 남깁니다.
6. 검수 대기가 되면 실제 원고·이미지를 확인하고 기존 승인 절차로 진행합니다.

보강 자료 검토 결과와 원고·출처도 체크포인트에 저장합니다. 중단 후 검토된 자료를 다시 수집·판정하거나 이미 보완한 글을 처음부터 쓰지 않도록 복구합니다. 보완 원고가 이미 완성됐고 검수만 남았으면 해당 원고부터 검수를 재개합니다. 원래 작업 파일을 변경하지 않고 재시도 복사본을 사용합니다.

기존 계정·설정·원고·이미지·이력·승인·발행 상태는 초기화하지 않습니다. 공백 제외 1,500자 목표(1,400~1,600자), 태그 15개, 볼드, 이미지 사용 시 기본 최소 4장, 중복 소재 허용과 동일 원고의 중복 발행 방지는 유지합니다. 이전 작업은 저장된 분량·태그 기준을 유지합니다. 링크 전용 방식은 키워드 없이 외부 검색을 추가하지 않으므로 보강 검색이 필요하면 키워드 + 링크 혼합 방식을 사용하세요.

확장 0.3.22는 변경하지 않았으므로 그대로 사용합니다. 새 PC에서는 함께 제공하는 BlogAuto-Extension-0.3.22.zip을 계속 보관할 폴더에 풀고 chrome://extensions → 개발자 모드 → 압축해제된 확장 프로그램 로드에서 manifest.json이 있는 extension 폴더를 선택해 연결합니다. 다운로드만으로 기존 PC의 계정 데이터가 자동 이전되지는 않습니다.

## 검증 범위

자동 테스트 240개 통과. 1,391자 → 1,488자 → 분량 충돌 거절을 재현해 키워드 자료 보강·검토된 사실과 출처 전달·1,500자 작성까지 4/5회로 완료하는 경로를 확인했습니다. 새 자료가 없으면 실제 다른 질문의 보강 시도를 5/5까지 진행하고 유료 Writer를 반복하지 않는 것, 무관한 자료·원문에 없는 인용·가짜 출처 거부, 중단 시 검토 결과 재사용, 매우 짧은 초안·첫 Writer 근거 부족 보강, 실제 최종 BLOCK 유지도 확인했습니다. HTML 제목 추출은 로컬 HTTP 서버로 검증했습니다.

격리된 실제 Electron 앱의 작업 이력 재시도에서 이전 1,488자 실패 원고를 불러와 모의 키워드 검색 1회 → Research 보강 사실 판정 1회 → 부분 Writer 보완 → Main 검수를 실행했습니다. 이전 라운드의 2회 기록을 보존하고 새 수동 라운드에서 3/5로 1,500자·태그 15개·볼드·내부 출처 2개·승인 전 원고까지 진행했습니다. Writer의 보강 사실·허용 출처 수신, 정상 조사 예산을 소진한 상태의 별도 제한 예산, 원래 체크포인트 보존, 화면 새로고침 후 횟수를 확인했습니다. AI와 검색은 모의 응답으로 검증했으며 실제 외부 검색·유료 AI·계정 발행·Windows GUI 실행은 수행하지 않았습니다.

Windows x64 패키지의 소스·버전·확장·네이티브 모듈을 확인하고, 공개 다운로드 파일의 크기·SHA-256과 다운로드 도우미의 파일 조합·압축 해제 결과를 검증합니다.
