# 네이버 블로그 자동화

Google Chrome 확장프로그램과 Codex CLI로 네이버·티스토리 글 생성 및 발행을 관리하는 Electron 앱입니다. 로그인은 사용자가 Chrome에서 직접 진행합니다.

## 실행

Node.js 24 이상, Google Chrome, 로그인된 Codex CLI가 필요합니다.

```sh
npm ci
npm start
```

개발 데이터는 기존 `runtime` 폴더에 저장됩니다. 업데이트 시 이 폴더를 유지하세요. 배포판은 OS의 앱 사용자 데이터 폴더를 사용합니다.

## 최초 연결

1. 앱에서 블로그 ID를 등록하고 **블로그 열기 / 로그인**을 실행합니다.
2. **크롬 확장 설치 → 설치 폴더 준비**로 확장 경로를 확인합니다.
3. 해당 Chrome의 `chrome://extensions`에서 개발자 모드를 켜고 **압축해제된 확장 프로그램을 로드합니다**로 폴더를 선택합니다.
4. 앱의 **확장프로그램 연결** 코드를 확장에 입력합니다.

계정별 Chrome마다 최초 연결이 필요합니다. 티스토리를 사용하면 공용 Chrome에도 로그인·연결하세요. 확장 업데이트 후에는 설치 폴더를 준비하고 확장 관리 화면에서 새로고침합니다.

## 벤치마크 형식과 수정·승인 문체

2026-10-23에 [doctorkidney](https://blog.naver.com/doctorkidney)와 [yogawarm](https://blog.naver.com/yogawarm)의 공개 글을 각각 3편씩 읽고 HTML 본문의 소제목·텍스트·이미지 배치를 확인했습니다. RSS는 글 주소를 찾는 데만 사용했고 관찰은 전체 공개 본문을 기준으로 했습니다. 다음은 표본의 구성 요소 수이며, 블로그 전체의 통계나 생성 목표가 아닙니다.

| --- | ---: | ---: |
| [doctorkidney · 2026-10-21](https://blog.naver.com/doctorkidney/224449125586) | 3 | 3 |
| [doctorkidney · 2026-10-19](https://blog.naver.com/doctorkidney/224446728850) | 4 | 11 |
| [doctorkidney · 2026-10-17](https://blog.naver.com/doctorkidney/224444553048) | 5 | 7 |
| [yogawarm · 2026-10-23](https://blog.naver.com/yogawarm/224450770624) | 6 | 16 |

| [yogawarm · 2026-10-22 · 스트레칭](https://blog.naver.com/yogawarm/224450015368) | 6 | 10 |

doctorkidney의 표본은 일상 상황이나 사례에서 궁금증을 만들고 설명과 판단 기준으로 이어집니다. yogawarm의 표본은 독자의 고민과 얻을 도움을 제시하고, 원리·순서·주의점으로 나누는 경향이 있습니다. 두 블로그 모두 짧은 텍스트 단위, 눈에 띄는 강조/소제목, 설명 주변의 이미지를 사용하지만 글의 종류에 따라 구성은 달랐습니다. 인용구 블록에는 소제목 외의 강조 문구도 포함됩니다.

앱에는 이 관찰을 일반화한 **공통 형식**, **설명 중심**, **실행 중심**을 넣었습니다. 기본은 공통 형식이며 본문 미리보기의 **내 글 문체 학습**에서 계정별로 선택하거나 끌 수 있습니다. 독자의 고민 → 핵심 답 → 이유/기준 또는 실행 방법 → 구체적인 마무리를 주제에 맞게 구성합니다. 섹션은 기존 네이버 인용구 소제목으로 표시하고 이미지는 설정 최대치 안에서 배치합니다. 원문의 사진 수, 잦은 줄바꿈, 고유 인사, 전문가 자격, 개인 경험, 의료 주장, 광고 문구는 재현하지 않습니다. 원문 전문이나 이미지를 앱·프롬프트·학습 자료로 배포하지 않습니다. 이 분석은 검색 순위나 건강 주장의 정확성을 검증한 결과가 아닙니다.

문체는 **사용자가 실제 수정하고 명시적으로 승인한 글만** 참고합니다.

1. **현재 원고를 수정 전후 칸에 불러오기**를 누르거나 수정 전 원고를 붙여넣습니다.
2. 최종 글 칸의 표현과 설명을 직접 고칩니다. 두 칸은 각각 200~12,000자이며, 긴 글은 대응하는 부분을 넣을 수 있습니다.
3. 승인 체크 후 **수정본 승인·학습**을 누릅니다. 내용을 다시 편집하면 승인 체크가 해제됩니다. 띄어쓰기만 바꾼 글과 승인하지 않은 글은 저장하지 않습니다. 직접 승인한 줄바꿈·문단 재구성은 형식 수정으로 학습합니다.

다음 새 글부터 승인된 최종 글의 줄바꿈·소제목을 유지한 짧은 발췌와 수정 전후 발췌를 기존 Writer 호출에 함께 전달합니다. 승인 예시에서 실제 문단·줄 길이를 계산하며, 소제목과 같은 줄에 있던 본문도 통계에서 누락하지 않습니다. 표현과 설명 방식만 참고하며 사례의 사실·수치나 개별 수정 내용을 새 주제의 사실 또는 일반 규칙으로 사용하지 않습니다. 승인 문체는 형식의 권장 문장 길이보다 우선하고 사실 근거와 필수 조건은 유지합니다. 모델 자체를 재훈련하지 않으며 학습·벤치마크를 위한 별도 AI 호출이나 매번의 블로그 재수집은 없습니다.

최종 예시와 수정 이력의 해시·짧은 비교 발췌는 계정별 로컬 `runtime/writing-memory`에 저장합니다. 최대 12개이며 목록에서 삭제할 수 있습니다. 이전 버전 예시는 보관하되 수정 전후와 승인을 확인할 수 없으면 **학습 제외**로 표시합니다. 다시 등록해 승인하면 적용됩니다. 학습용 편집은 현재 발행 원고를 바꾸지 않으며, 재개하는 작업은 처음 시작할 때의 문체·형식 설정을 사용합니다.

형식 v2는 조사 단계의 구성안부터 적용하고, 작성 결과의 소제목 앞 도입·본문이 있는 소제목 2개 이상·긴 문단 분리를 확인합니다. 최종 검수는 실제 도입·마무리 인용과 소제목으로 형식 적용을 판정하며, 형식이 반영되지 않은 글은 통과시키지 않습니다. 승인 문체에 따라 문단 길이 기준을 조정합니다. 본문 아래에 실제 사용한 형식 버전·소제목·문단·승인 예시 수를 표시하고, 작업 로그에도 재개 여부와 적용 설정을 남깁니다.

Windows 0.2.6-rc.3부터 확장 0.3.17(편집기 빌드 20261023.1)이 필요합니다. 앱에서 **확장 설치 → 설치 폴더 준비**를 실행한 뒤 해당 계정 Chrome의 `chrome://extensions`에서 BlogAuto를 새로고침하세요. 업데이트된 확장은 벤치마크 원고의 문단 사이 빈 줄과 문단 안 줄바꿈을 보존합니다. 구버전 확장은 AI 생성 전에 안내하고 중지합니다. 기존 중단 원고는 보존해 원래 설정으로 재개하므로 새 형식 적용을 원하면 기존 작업 취소 후 새 글을 시작합니다.

기본 토큰 절약 모드에서는 Writer 자체 다듬기와 최종 품질 검수를 사용하고, 품질 보완은 최대 한 번으로 묶습니다. 형식·문체 선호 차이만으로 글을 무한 재작성하지 않습니다. 생성 품질과 네이버 노출은 보장하지 않습니다.

## 배포

```sh
npm run dist           # Windows 휴대용 EXE: Windows에서 실행
npm run dist:mac:arm64 # Apple Silicon DMG: macOS에서 실행
npm run dist:mac:x64   # Intel DMG: macOS에서 실행
```

결과물은 `dist`에 생성되며 테스트·개인 데이터는 제외합니다. macOS에서는 `npm ci`를 새로 실행하세요. macOS 대응은 코드·모의 환경을 검증했으며 실제 Mac 실행·설치는 미검증입니다. 코드 서명·공증은 별도 설정이 필요합니다.
